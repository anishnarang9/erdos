## Working invocation from Windows

```

```

with the script starting `export PATH=/root/.local/bin:$PATH` and `cd "/mnt/c/Users/nslep/Desktop/VS Code Projects/UBC-26/contracts"` (quoted). `wsl -e bash -lc "..."` also works for one-liners without special characters. `which forge anvil` finds nothing in WSL, so there is no upstream Foundry to confuse with.

## Network selection: which mode runs Arc rules

Verified with the scratch project (`ForkProbe.t.sol`, `LocalArc.t.sol`, `Deal.t.sol`, in the scratchpad `research/forkproj`, solc 0.8.28, cancun, same settings as `contracts/foundry.toml`).

| Command | Arc rules? | Result |
| --- | --- | --- |
| `arc-forge test` (no flag, no fork) | **No**: Ethereum rules, chainid 31337, no USDC at `0x3600...` | 10 of 11 probe tests fail (all USDC calls revert). This is the trap the arc-foundry README warns about. |
| `arc-forge test --network arc` | Yes, local | `0x3600...0000` is deployed locally (code length 1798, `decimals()` = 6), `vm.deal` native 18-dec balances show in 6-dec `balanceOf`. Chainid is still 31337, block 1. The seeded testnet blocklist is **not** present (see below). |
| `arc-forge test --fork-url https://rpc.testnet.arc.io` | Yes (auto-detected from the forked chain) | All 11 probe tests pass in ~1.5 s. chainid 5042002, real block number. |
| `arc-forge test --network arc --fork-url ...` | Yes | Same 11 pass. |
| `arc-forge test --fork-url ... --fork-block-number 72387259 -vvvv` | Yes | Works; traces show the Arc precompile. |

`--network` possible values (from `arc-forge test --help`): `ethereum, optimism, tempo, arc`. A foundry.toml profile can set `network = "arc"` instead of a flag (arc-foundry README, "Point a project at Arc"): `[profile.arc]` `network = "arc"`, then `FOUNDRY_PROFILE=arc arc-forge test`.

## Fork test: exact observations

Fork command and result (excerpt, `-vv`):

```
arc-forge test --fork-url https://rpc.testnet.arc.io -vv
[PASS] test_reads()   chainid 5042002  block 72387502  decimals 6
                      balanceOf(HOLDER) 231166172603769004   balanceOf(BLOCKED) 13489266
[PASS] test_transferEOAToEOA()               (vm.prank(HOLDER) USDC.transfer(0xA11CE, 1e6): ok; to.balance == 1e6 * 1e12)
[PASS] test_transferIntoAndOutOfContract()
[PASS] test_transferToBlocklistedReverts()   (revert string "Blocked address")
Suite result: ok. 9 passed (first run), later 11 passed with the added tests
```

- `decimals()` on `0x3600000000000000000000000000000000000000` returns 6; `balanceOf` of the testnet whale `0x4E42177AB52202Ced872A5EF661dfc4794bB37bF` is readable; `vm.prank(HOLDER)` then `USDC.transfer(...)` works on the fork, with `to.balance` showing the same value times 1e12 (native 18-dec view).
- **`vm.deal(addr, amount18)` works on the fork and locally and is reflected in the ERC-20 view** (`vm.deal(a, 7e18)` gives `USDC.balanceOf(a) == 7e6`). `deal(address(USDC), a, x)` (forge-std token deal) **reverts** on both fork and local arc: use `vm.deal` with 18-decimal native amounts, not the std token `deal`.
- Revert trace on the fork (`-vvvv`) shows the path: `0x3600...::transfer` then `delegatecall` into implementation `0xC6AD664ac6679F4Ce74e10E91449C93Ec1ae3cA6` then a call into the native coin precompile `0x1800000000000000000000000000000000000000::transfer(from, to, 1e12)` which reverts with `Blocked address`. So the ERC-20 token itself delegates movement to a precompile and the blocklist is enforced there.
- Fork block numbers are live, so the whale balance drifts per run. Tests should pin `--fork-block-number` or, better, fund their own addresses with `vm.deal`.

## Local blocklist seeding (no fork)

`arc-forge test --network arc` does not seed the testnet blocklist: `0x70997970C51812dc3A010C7d01b50e0d17dc79C8` was not blocked there (native send ok, ERC-20 transfer ok). To exercise the revert locally, write the blocklist slot into the NativeCoinControl precompile, as arc-foundry's own tests do (`crates/forge/tests/cli/arc.rs` at v0.8.0-4):

```solidity
address constant NCC = 0x1800000000000000000000000000000000000001;
vm.store(NCC, keccak256(abi.encode(blocked, uint256(2))), bytes32(uint256(1)));
```

Verified locally with `--network arc` (`LocalArc.t.sol`): before the store, `USDC.transfer(blocked, 1e6)` succeeds; after it, both `transfer` to the blocked address and `transfer` from it revert with `Blocked address`.

## arc-anvil

Verified in WSL:

- `arc-anvil --network arc --port 18545` starts in under 4 s. `eth_chainId` returns `0x7a69` (31337). `eth_call` `decimals()` on `0x3600...` returns 6. Latest block `baseFeePerGas` = 20000000000 (20 gwei), `gasLimit` = 30000000. Ten funded dev accounts from the public test mnemonic (account (1) is `0x7099...79C8`, the same address the docs seed as blocklisted on testnet). Killed afterwards.
- `arc-anvil --fork-url https://rpc.testnet.arc.io --port 18546` starts; `eth_chainId` returns `0x4cef52` (5042002). `arc-cast call 0x3600... "decimals()(uint8)"` returns 6, `balanceOf` works.
- On that fork, `anvil_impersonateAccount` (returns `null`) then `arc-cast send ... --from <whale> --unlocked --gas-price 20gwei` of `transfer(address,uint256)` to a fresh address succeeded (`status 1`, `gasUsed 48722`, `effectiveGasPrice 20000000000`). The receipt has **two** Transfer logs: one from the system emitter `0xfffffffffffffffffffffffffffffffffffffffe` with data `0x0de0b6b3a7640000` (1e18, the 1e6 transfer in 18-dec) and one from `0x3600...` with value `0xf4240` (1e6, 6-dec). Event consumers must not double count.
- `arc-cast send ... transfer(blocklisted, 1)` on the fork fails at gas estimation with `execution reverted: Blocked address`.
- anvil admission check (arc-foundry source `crates/anvil/src/eth/backend/mem/mod.rs`, around line 4719): the sender, and the recipient when value is non-zero, are checked against NativeCoinControl and rejected with `transaction rejected: address <a> is blocklisted by NativeCoinControl`.

Note: a process `arc-anvil --network arc --port 8555` (pid 743) was already running in WSL during these checks. It was not started by this task and was left alone.

## Recommended acceptance flags

1. Local acceptance (S-series that do not need live state): `arc-forge test --network arc` (or `FOUNDRY_PROFILE=arc` with `network = "arc"` in a `[profile.arc]`). Never run acceptance with bare `arc-forge test`, which silently tests Ethereum rules. Seed any blocklist scenario with the `vm.store` line above, fund accounts with `vm.deal(addr, usdc6 * 1e12)`.
2. Fork acceptance (anything that needs real Arc state or the seeded blocklisted address): `arc-forge test --network arc --fork-url https://rpc.testnet.arc.io --fork-block-number <pinned block>`; `--network arc` is redundant with `--fork-url` but explicit. Fork tests can use the real blocklisted address `0x70997970C51812dc3A010C7d01b50e0d17dc79C8`, `vm.prank` of any real holder, and `vm.deal`.
3. Local node for scripts/cast: `arc-anvil --network arc` (chainid 31337) or `arc-anvil --fork-url https://rpc.testnet.arc.io [--fork-block-number N]` (chainid 5042002).
4. Tool versions to record in CI/docs: release `v0.8.0-4`, commit `3e95efaeaaaca64d6ac9c1ee988968683dbd0d22`. Do not use `foundry-rs/foundry-toolchain` (README warning).
