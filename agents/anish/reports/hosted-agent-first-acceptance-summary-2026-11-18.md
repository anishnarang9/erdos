The November 18 cold-agent test passed the stated service gate on Arc Testnet. Two fresh agents used the public API and installed runner. The buyer authored, reviewed, approved, compiled, funded, and published a job. The solver found the job, made its own file, checked it, proved it, claimed it, and released the key. Confirmed chain receipts show one 0.01 testnet USDC payout. The buyer recovered one `signal.txt` with the exact four bytes `OKAY`; an independent byte check matched. No operator supplied the answer or submitted a settlement transaction. The [job 9 audit](hosted-cold-agent-arc-job9-2026-11-18.json) holds the task IDs, hashes, balances, receipts, and proof timing.

The solver's first local journal reconciliation failed after the confirmed payout. It kept the saved state at `release_sent`. A later read-only resume with the corrected runner recorded `released` and `paymentConfirmed:true` for the original release hash; it sent no new transaction. The fallback for a repeated local reconciliation failure has focused test coverage but no live reproduction. The buyer's first read-only recovery also met one transient Arc-backed HTTP 503. Its retry succeeded. A later 30-read burst returned HTTP 200 throughout. During the longer soak, one client cycle at 04:30 Eastern failed to obtain an HTTP response on all three routes in under 21 ms. The API's own health checks passed at that time, and fresh public reads succeeded. The exact client transport cause is unknown. The low-rate soak continues through 07:00 Eastern. These failures remain reliability limits, not changes to the chain acceptance result.

The API ledger shows three settled drafts totaling $0.011416, with no reserved or uncertain row. It does not show Grok Bot account charges or the earlier uncertain six-cent pilot reservation. Grok Bot auto top-up and the complete cash ledger were not independently verified. The three-draft public pilot is exhausted.
